## Open questions

- **Migrations vs live DB.** No migration adds `profile_id` to `daily_logs`, `meals` or
  `workout_sets`, but the live tables have it (zero-row REST selects returned 200; a bogus
  column returned 400). The Diary filters on it explicitly. The web `STATUS.md` records the
  same `daily_logs` key drift.
- **Sports/Crew have no backend.** No `user_sports` table and no create/join squad functions;
  both screens are labelled "not saved yet".
- **`squad_members` RLS policy reads `squad_members` itself** — likely infinite recursion.
  Not reproduced.
- **Web `/api/log` flags English as Roman Urdu on one keyword hit** (`the`, `he`, `na`). Seen:
  "what is the capital of France" got the Urdu refusal. Fix belongs in `../fitness`.
- **Status bar icons are white on the light background.** Pre-existing; nothing sets a style.
- **API base URL** is `http://localhost:3000` via `adb reverse` — dev only. No deployed URL
  decided.
- `src/lib/goalAdvisor.ts` is a verbatim web port, so it carries the web's reproduced
  macro-% rounding bug (totals of 101). Native uses only `bmr`, `tdee`, `recCalories`, so no
  screen shows it.
- Possibly unused dependencies: `expo-symbols`, `expo-glass-effect`, `expo-web-browser`. Unchecked.
